# Метрики модели и мониторинг деградации

Метрики рассчитывает `evaluate_model.py`: accuracy, precision/recall/F1 по классам,
macro/weighted averages, support и confusion matrix. `confidence` предсказания
не является метрикой фактической точности.

## Диагностика и история

```bash
poetry run python evaluate_model.py \
  --model model_checkpoint.pth \
  --data my_dataset/current_reviewed \
  --per-class 0 \
  --output reports/current_reviewed.json \
  --metadata reports/current_dataset_review.json \
  --history reports/model_metrics_history.jsonl
```

Пути обозначают подготовленный набор и его метаданные. Без `--metadata` отчёт
получает статусы unreviewed / independent_test=false. С `--per-class 0` проверяются
все изображения; положительное значение ограничивает число на класс с seed 42.

История JSONL содержит время UTC, хеши весов и выборки, метрики, статусы проверки
данных. Отпечаток выборки связывает метки папок и байты изображений независимо
от порядка файлов. Для воспроизводимого теста сравнивайте одинаковый набор;
при мониторинге разных периодов контролируйте метод отбора и состав данных.

## Подтверждение данных

```json
{
  "dataset_sha256": "отпечаток полного проверенного набора из отчёта",
  "label_review_status": "reviewed",
  "reviewer": "имя проверившего разметку",
  "independent_test": true,
  "provenance_notes": "источники и выполненная проверка пересечений с обучением"
}
```

Это пример структуры, а не готовое подтверждение имеющихся данных. Для получения
отпечатка сначала выполните диагностику без metadata, затем после реальной проверки
оформите метаданные и повторите запуск с `--metadata`. Проверяется совпадение
отпечатков; истинность происхождения данных подтверждает сопровождающий проекта.

## Деградация и повторное обучение

[RETRAINING.md](RETRAINING.md) описывает сравнение базового и текущего периодов,
относительные пороги ухудшения, подготовку данных, обучение отдельного кандидата,
защиту от повторных запусков и ручное решение о замене модели.

API пока не собирает правильные метки пользователей. Поэтому мониторинг требует
разметки выборок новых загрузок и запуска команды на подготовленных отчётах.
Изменение распределения категорий/confidence может быть сигналом сдвига данных,
но не доказывает ухудшение классификации.

## Старые абсолютные пороги

`check_model_metrics.py` и `model_metrics_policy.json` сохранены как необязательный
локальный инструмент проверки отчёта. Флаг `--policy` у оценщика позволяет
применить эти пороги явно. В CI и деплое абсолютные пороги больше не используются;
для деградации применяется отдельная `retraining_policy.json`.
