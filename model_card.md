# Model Card: PhotoClassifier — PhotoDistribution

**Дата обновления:** 2 ноября 2026 года.  
**Назначение документа:** описание модели, условий её применения и ограничений.
Структура соответствует девяти разделам Google
[Model Cards for Model Reporting](https://research.google/pubs/model-cards-for-model-reporting/).

| Лицензия | Лицензия текущих весов и исходных обучающих данных не документирована |

Карточка относится к локальному checkpoint с SHA-256:

`aa3c2df52bce6fdbd8b789c3323e61268fedc25d0cc7e94a5a84a146cd1cfa7c`

## 2. Назначение (Intended Use)

### Бизнес-задача и пользователи

Модель помогает сократить ручную сортировку фотоархива. Пользователь загружает
изображения, сервис определяет их тему и помещает исходные файлы в папки Nextcloud.
Целевые пользователи — владельцы фотоархивов и команды с общим хранилищем.

### Предусмотренный сценарий

Модель вызывается в `POST /upload/` после проверки файлов. Она определяет
категорию, а приложение выбирает папку и загружает файл. Пользователь получает
результат обработки и может проверить правильность размещения.
Модель не управляет хранением, авторизацией и правами доступа.

### Входные данные

| Уровень | Данные и обработка |
|---|---|
| API | Файл изображения в multipart/form-data; проверяются MIME-тип, размер и содержимое Pillow |
| Модель | Байты изображения; имя файла используется только для журналирования |
| Предобработка | Декодирование, преобразование в RGB, Resize до 224 × 224, ToTensor и Normalize |
| Входной тензор | `[1, 3, 224, 224]`: одно изображение, три цветовых канала |
| Нормализация текущей модели | mean: `[0.485, 0.456, 0.406]`; std: `[0.229, 0.224, 0.225]` |

Параметры размера и нормализации читаются из checkpoint. По умолчанию API принимает
до 20 файлов за запрос, не более 10 МиБ каждый; ограничения настраиваются.

### Выходные данные

При успешной классификации возвращаются `success`, индекс `class_idx`,
название категории `class_name` и `confidence`. Категория выбирается через
argmax выходных логитов, confidence — softmax выбранного класса.

| Индекс текущей модели | Категория | Значение |
|---|---|---|
| 0 | `animals` | Животные |
| 1 | `city` | Городские сцены |
| 2 | `documents` | Изображения документов |
| 3 | `nature` | Природа |
| 4 | `people` | Люди |

Порядок категорий берётся из checkpoint. Приложение использует `class_name`
как имя папки Nextcloud, сохраняет исходные байты под уникальным именем и
возвращает категорию и confidence для успешно сохранённых файлов.
При обработанной ошибке inference возвращаются `success: false` и описание ошибки.

### Сценарии вне назначения

Модель не предназначена для идентификации людей, OCR, проверки подлинности
документов, определения прав доступа или модерации опасного контента.
Категория documents характеризует внешний вид изображения, а не его содержание
в юридическом или текстовом смысле.

## 3. Факторы качества (Factors)

На предсказания могут влиять:

- освещение, размытие, шум, ракурс, фон и разрешение;
- рисунки, скриншоты и другие отличия от обучающих фотографий;
- смешанные сцены: человек с животным или человек на фоне города;
- изменение пропорций при Resize до квадрата и потеря мелких деталей;
- дисбаланс классов и изменение источников новых загрузок.

Для смешанных сцен необходимо заранее установить правила разметки, поскольку
модель возвращает только одну категорию. Равномерное качество по условиям съёмки,
источникам изображений и группам людей не подтверждено.

## 4. Метрики (Metrics)

Метрики рассчитываются по предсказаниям и проверенным человеком меткам.

| Метрика | Назначение |
|---|---|
| Accuracy | Общая доля изображений с верно выбранной категорией |
| Precision по классу | Какая доля назначений в папку соответствует правильной категории |
| Recall по классу | Какая доля изображений категории была найдена моделью |
| F1 по классу | Баланс precision и recall отдельной категории |
| Macro-F1 | Среднее F1 с одинаковым весом всех категорий; важно при дисбалансе |
| Weighted-F1 | Среднее F1 с учётом численности категорий |
| Support | Число размеченных примеров; контекст для интерпретации метрик |
| Confusion matrix | Направления ошибок между категориями |

Во время обучения рассчитываются loss и accuracy; Optuna использует validation
accuracy для выбора параметров. Confidence отдельного ответа не является
метрикой точности и не подтверждён как калиброванная вероятность.

Порог отказа от классификации отсутствует: при успешном inference выбирается
одна категория даже при низкой уверенности. Для бизнес-оценки дополнительно
полезны доля ручных исправлений и время сортировки; их измерение в API не реализовано.

## 5. Данные оценки (Evaluation Data)

Текущий pipeline выделяет 20% локального ImageFolder на validation с seed 42.
Разбиение случайное, без стратификации и группировки похожих серий.
На validation применяются Resize, ToTensor и Normalize без случайных аугментаций.

Validation используется и при подборе гиперпараметров, и для финальной проверки
в скрипте обучения; она не заменяет независимый test-набор.
Исходное разделение данных перенесённого checkpoint неизвестно.

Для независимого теста требуются отдельные изображения с проверенными метками,
без совпадений и похожих кадров из обучения. Поисковые категории внешних
изображений не следует считать достоверной разметкой без проверки человеком.

## 6. Обучающие данные (Training Data)

Код обучения использует структуру ImageFolder:

```text
my_dataset/train/
├── animals/
├── city/
├── documents/
├── nature/
└── people/
```

Название папки задаёт целевую категорию. Источники, лицензии, даты сбора и правила
разметки исходных данных не документированы в достаточной степени. Наличие
локального набора не доказывает, что именно его текущая версия использовалась
для получения legacy-checkpoint.

Текущий `auto_ml.py` использует случайное горизонтальное отражение, повороты
до ±15° и нормализацию. Дисбаланс компенсируется весами CrossEntropyLoss,
рассчитанными по train. Отражение может быть неуместно для изображений документов
с текстом; его влияние нужно проверять отдельно.

Seed фиксируется для Python, NumPy и PyTorch. Для воспроизводимости необходимы
также зафиксированный состав данных, конфигурация, версии зависимостей и веса.

## 7. Количественный анализ (Quantitative Analyses)

По принятому формату этой карточки численные результаты оценок не включены.
Отсутствие таблиц результатов не означает, что качество модели подтверждено
или что оценка никогда не выполнялась.

Для полноценного анализа следует отдельно представлять результаты на независимом
наборе: общие метрики, метрики каждого класса, матрицу ошибок и размеры выборок.
Полезны срезы по источнику и качеству снимков, а также по смешанным сценам.
Без подтверждённых результатов нельзя заявлять гарантированную точность.

## 8. Этические аспекты (Ethical Considerations)

Фотографии людей и документов могут содержать персональные и чувствительные
данные. Необходимо определить разрешения на обработку, доступ к файлам и сроки
хранения. Пользовательская авторизация API пока не реализована; маршруты загрузки,
просмотра и удаления доступны без входа.

Ошибочная категория может поместить файл в неожиданную папку. Папка, выбранная
моделью, не должна автоматически определять доступ других пользователей.
Модель не предназначена для определения личности или свойств человека.
Качество для разных групп людей отдельно не подтверждено.

Перед распространением исходных данных или весов нужно уточнить права на них.
Информация о лицензиях внешних кандидатов не заменяет лицензирование исходного
обучающего набора.

## 9. Ограничения и рекомендации (Caveats and Recommendations)

- Модель ограничена пятью классами: нет категории «другое», обнаружения неизвестного
  содержимого и одновременного назначения нескольких меток.
- Вход, не соответствующий известным категориям, всё равно может получить одну
  из них. Confidence не гарантирует правильность выбора.
- Успех загрузки означает сохранение файла, а не проверку правильности категории.
- Рекомендуется предусмотреть ручную проверку и исправление ошибочных назначений.
  Для загрузок с согласием доступно явное подтверждение или исправление категории;
  пользовательские метки требуют проверки перед обучением.
- Повторное обучение запускается отдельным сценарием на проверенных отчётах.
  Новая модель сохраняется кандидатом; публикация и откат выполняются вручную.
- При изменении весов, классов, предобработки или данных карточку нужно обновлять.
